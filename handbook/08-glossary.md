# 08 - Glossary

Yocto and embedded Linux vocabulary, mapped to RTOS and bare-metal equivalents
where an honest mapping exists. Where it does not, the entry says so -- a
misleading analogy costs more than no analogy.

---

## Build system

| Term | What it is | RTOS equivalent |
|---|---|---|
| **BitBake** | The build engine. Parses recipes, resolves dependencies, schedules tasks. | Make / CMake, for an entire OS |
| **OpenEmbedded (OE)** | The metadata and recipe collection BitBake executes. | -- |
| **Yocto Project** | The umbrella: OE-core plus releases, tooling and an LTS policy. | -- |
| **Poky** | The historical reference distro and combo-layer repo. Deprecated as a combo repo; consume `openembedded-core`, `bitbake` and `meta-yocto` directly. | -- |
| **KAS** | Orchestrator above BitBake: clones pinned layers, writes `bblayers.conf` and `local.conf`, optionally runs it all in a container. | `west.yml` / a repo manifest |
| **Recipe** (`.bb`) | Build instructions for one package: fetch, configure, compile, install, package. | A component's build script |
| **`.bbappend`** | A thin override on someone else's recipe. Never fork a recipe you can append to. | A patch or config overlay |
| **Layer** (`meta-*`) | A git repo of recipes and config, with a priority. The unit of reuse. | A middleware or BSP package |
| **`BBFILE_PRIORITY`** | Which layer wins when two define the same recipe. Higher wins. Vendor BSP layers are commonly 9. | Include-path order |
| **Class** (`.bbclass`) | Shared recipe logic, pulled in with `inherit`. | A build-system macro / template |
| **Task** | One step of a recipe: `do_fetch`, `do_configure`, `do_compile`, `do_install`, `do_package`. Addressable: `bitbake -c compile <recipe>`. | A make target |
| **sstate-cache** | Shared-state cache of task outputs. What makes a rebuild minutes instead of hours. | `ccache`, but for every task |
| **`DL_DIR`** | Downloaded source archives and bare git mirrors. | A vendor/ directory |
| **`SRCREV`** | The pinned source revision. Must be a commit; `${AUTOREV}` destroys reproducibility. | A submodule commit |
| **`devtool`** | The iteration tool: `modify`, `build`, `deploy-target` a package without reflashing. | Flash-and-pray, replaced |
| **`wic`** | The image composer: turns a rootfs into a partitioned disk image from a `.wks`. | A flash-layout script |

## Configuration

| Term | What it is | RTOS equivalent |
|---|---|---|
| **`MACHINE`** | Which board you are building for. Selects one machine conf. | Board select in your build config |
| **Machine conf** | The BSP definition: SoC, kernel, device tree, console, storage layout. | Your BSP |
| **`DISTRO`** | Which distro conf: global feature policy across every image. | A build-time config header |
| **`DISTRO_FEATURES`** | Global capability flags (`systemd`, `wifi`, `opengl`). Adding one can pull in a large dependency tree. | `CONFIG_*` at the system level |
| **`IMAGE_FEATURES`** | Per-image flags (`debug-tweaks`, `ssh-server-dropbear`, `tools-debug`). | -- |
| **Image recipe** | The package list that becomes the rootfs. | Your link list / final binary |
| **`local.conf`** | Per-build settings. Generated by KAS here -- do not hand-edit it in a KAS project. | Local build overrides |
| **`bblayers.conf`** | Which layers are active. Also KAS-generated. | Include paths |
| **`PACKAGE_CLASSES`** | Target package format: `package_ipk`, `package_rpm`, `package_deb`. | -- |
| **Overrides** (`:append`, `:remove`, `:machine`) | Context-sensitive variable modification, e.g. `SRC_URI:append:rpi5-devkit`. Powerful and the usual source of "why is this value not what I set?". | Conditional compilation |

## Boot and runtime

| Term | What it is | RTOS equivalent |
|---|---|---|
| **BootROM** | On-die, mask-programmed first stage. Not replaceable. | Your chip's boot ROM -- identical concept |
| **TPL / SPL** | Tiny/secondary program loaders. On Rockchip, TPL is the closed DDR-init blob. | Early clock and DRAM init in startup code |
| **TF-A / BL31** | ARM Trusted Firmware, the EL3 runtime that stays resident. | No equivalent -- new territory |
| **OP-TEE / BL32** | Trusted execution environment, optional secure world. | No equivalent |
| **U-Boot** | The bootloader proper: reads config, picks kernel and device tree, hands off. | Your startup and HAL init |
| **MaskROM / recovery** | Vendor USB recovery mode from the BootROM. Rockchip: VID `2207`, driven by `rkdeveloptool`. | A bootloader/DFU mode |
| **Device tree** (`.dtb`, overlays) | Hardware description passed to the kernel, so one kernel binary serves many boards. | Board header files and pin config, moved to data |
| **`initramfs`** | Optional early rootfs in RAM, for setup before the real root mounts. | -- |
| **systemd** | Init system and service manager: dependency-ordered startup, restarts, logging. | Your scheduler and task table, roughly |
| **`journalctl`** | The system log. `journalctl -b` for this boot. | Your trace/printf buffer |
| **rootfs** | The root filesystem. Often built small and grown to fill the medium on first boot. | -- |
| **A/B slots** | Two OS copies so an update can fail and roll back. | -- |

## Product lifecycle

| Term | What it is |
|---|---|
| **OTA** | Over-the-air update. RAUC, swupdate and Mender are the usual candidates. |
| **RAUC** | Update framework: signed bundles installed into slots. |
| **SBOM** | Software bill of materials -- everything in the image and its licence. Yocto generates SPDX via `create-spdx`. |
| **`cve-check`** | BitBake class that reports known CVEs against the recipes in an image. |
| **`LICENSE_FLAGS_ACCEPTED`** | Explicit opt-in for recipes with commercial or restricted licences. Declare per image, justify each entry. |
| **LTS** | Long-term support release with security fixes for years. wrynose 6.0 is supported to April 2030. |
| **Secure boot** | Signature verification through the boot chain, rooted in fused keys. Irreversible once fused. |
| **Provisioning** | Writing per-device identity (serial, MACs, keys) in the factory. |

## Words that mean something specific here

- **"Machine"** means a board, not a computer. Your build host is the *host*.
- **"Native"** means built to run on the build host (`-native` recipes), not
  "unmodified".
- **"Target"** is overloaded: the board you are building for, and also the
  BitBake target (`bytelab-image`). Usually clear from context.
- **"It builds"** is not "it boots", and "it boots" is not "it boots on the
  product hardware". In this domain the distinction is the whole game -- see the
  template README's status table for how to state it honestly.
